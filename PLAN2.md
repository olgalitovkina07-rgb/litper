# PLAN2.md — план лабораторной работы №2

## Вариант

**Вариант 4 — «Справочник контактов»**, структура данных: **префиксное дерево (Trie) по имени**.

## Цель

Реализовать собственное префиксное дерево на массивах и собственных узлах (без `java.util`-коллекций
как хранилища), дополнительные операции варианта (автодополнение по префиксу, подсчёт контактов
в поддереве), визуализацию внутреннего устройства структуры и асинхронные операции с прогрессом
и отменой.

Модель данных из лабораторной №1 не меняется: `Contact` / `EmergencyContact` / `CorporateContact`.

---

## Этап 1. Собственная структура данных

- [ ] `structure/KeyExtractor` — функциональный интерфейс «как получить ключ из значения».
- [ ] `structure/TrieNode` — собственный узел:
  - символ;
  - дети в **собственном массиве**, отсортированном по символу (бинарный поиск);
  - значения в терминальном узле (свой массив, несколько контактов с одинаковым именем);
  - счётчик контактов в поддереве.
- [ ] `structure/Trie<T>` — дженерики (`Trie<Contact>`):
  - `insert`, `findAll`, `findNode`, `remove`, `removeKey`, `removePrefix`;
  - `autocomplete(prefix, limit)`, `countByPrefix(prefix)`;
  - `toArray()` — алфавитный снимок;
  - трассировка последнего обхода (`lastTrace()`, `lastOperation()`) для подсветки в GUI;
  - все публичные операции `synchronized`.

### Асимптотика (σ — размер алфавита, L — длина имени, N — число контактов)

| Операция | O(...) | Обоснование |
|---|---|---|
| `insert` | O(L·log σ) | спуск по L символам, в каждом узле бинарный поиск ребёнка |
| `findAll` / `findNode` | O(L·log σ) | то же |
| `remove` | O(L·log σ) | спуск + удаление из терминального узла + подрезка пустых узлов |
| `removePrefix` | O(σ + L·log σ + K) | спуск + обход удаляемого поддерева размера K |
| `autocomplete` | O(L·log σ + K) | спуск по префиксу + сбор K найденных контактов |
| `countByPrefix` | O(L·log σ) | спуск + чтение счётчика в узле (O(1)) |
| `toArray` | O(N + V) | обход всех V узлов, выдача N контактов |

## Этап 2. Сервис и хранилище

- [ ] `service/ContactService` — основное хранилище теперь `Trie<Contact>` (списки запрещены).
- [ ] Ключ индексации — имя в нижнем регистре, чтобы поиск не зависел от регистра.
- [ ] Операции: `add`, `update` (переиндексация при смене имени), `remove`, `suggest`,
  `countByPrefix`, `getAll` (алфавитный снимок-массив).
- [ ] `service/ContactGenerator` — генерация набора данных:
  - [ ] задаётся число контактов и seed (детерминированно);
  - [ ] прогресс по шагам;
  - [ ] отмена через `CancellationException`;
  - [ ] генерируются только редактируемые (`CorporateContact`) — read-only появляются из файла.

## Этап 4. Визуализация

- [ ] `gui/TriePanel` — панель с `Canvas`:
  - [ ] своя раскладка: y — глубина, x — позиция листа (классическая tidy-раскладка);
  - [ ] полная перерисовка после каждой операции;
  - [ ] подсветка узлов, посещённых при последней операции (из `Trie.lastTrace()`);

  - [ ] ограничение числа отрисованных узлов, чтобы 10⁵ контактов не рисовались целиком;
  - [ ] поле префикса, автодополнение (список подсказок), «Найти», «Удалить по имени»,
        «Удалить по префиксу»;
  - [ ] статистика: узлов, контактов, контактов по префиксу.
