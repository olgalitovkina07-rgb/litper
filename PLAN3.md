# PLAN3.md — план лабораторной работы №3

## Вариант

**Вариант 4 — «Справочник контактов».**

## Цель

Добавить сериализацию и десериализацию данных через общий интерфейс (минимум два
формата: JSON и бинарный), доработать GUI экспортом/импортом через `FileChooser`,
выполнить сравнение форматов и покрыть базовые операции JUnit-тестами.

Модель данных (`Contact` / `EmergencyContact` / `CorporateContact`) и хранилище
(префиксное дерево `Trie`) не меняются.

---

## Этап 1. Общий контракт сериализации

- [x] `persistence/serialize/Serializer<T>` — `format()`, `fileExtension()`,
      `save(T, Path)`, `load(Path)`.
- [x] `SerializationException` — отдельная ошибка чтения/записи и битых файлов.
- [x] `ContactRecord` — плоская запись контакта (те же поля, что в CSV).
- [x] `ContactData` — `schemaVersion` + массив записей.
- [x] `ContactSerializers` — доступ к форматам и выбор по расширению файла.

## Этап 2. Реализации форматов

- [x] `JsonContactSerializer` (Jackson) — с отступами, для чтения глазами.
- [x] `BinaryContactSerializer` — собственный формат: метка `LITP`, версия,
      число записей, семь строк на запись.
- [x] Версия схемы пишется в оба формата и проверяется при чтении.
- [x] Чужой/обрезанный/повреждённый файл дают понятную `SerializationException`.

## Этап 3. GUI

- [x] Кнопки «Экспорт» и «Импорт».
- [x] `FileChooser` с фильтрами `*.json` и `*.bin`; формат по расширению.
- [x] Экспорт и импорт выполняются в фоне через `Task` (прогресс/отмена доступны).
- [x] После импорта обновляются таблица и визуализация дерева.
- [x] Ошибки показываются диалогом.

## Этап 4. Сравнение форматов

- [x] `SerializationBench` — размер файла, среднее время сохранения/загрузки
      за 5 прогонов, фрагмент каждого файла.
- [x] Gradle-задача `serializationBench` (число записей через `-Pcount=`).
- [x] Перенести цифры и фрагменты в отчёт (DOCX).

## Этап 5. Тесты

- [x] DTO: конвертация туда и обратно, пустые поля, ошибки.
