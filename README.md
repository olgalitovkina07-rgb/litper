# Справочник контактов

Лабораторные работы №1–2, **вариант 4 «Справочник контактов»**.

JavaFX-приложение для ведения справочника контактов: загрузка и сохранение CSV,
отображение в таблице, добавление и редактирование контактов, **собственное
префиксное дерево (Trie) по имени** с визуализацией и асинхронными операциями.

## Требования

- JDK 21+ (рекомендуется 25) — проверено на JDK 25
- Остальные зависимости подтягивает Gradle Wrapper автоматически

gradlew.bat run        # Windows

## Формат CSV

Файл UTF-8, первая строка — заголовок, разделитель полей — точка с запятой `;`.
Один контакт — одна строка. Значения с символом `;` внутри не поддерживаются.

```text
type;name;phone;email;organization;position;internalNumber
corporate;Иван Иванов;+79990000000;ivan@example.com;ООО Ромашка;Инженер;123
emergency;Пожарная служба;101;;МЧС;;
```

| Поле | Значение |
|---|---|
| `type` | `corporate` (корпоративный) или `emergency` (аварийный) |
| `name`, `phone` | обязательные для обоих типов |
| `email`, `organization` | необязательные |
| `position`, `internalNumber` | только для `corporate`; внутренний номер — только цифры |

Битые строки (неверное число полей, неизвестный тип, нечисловой внутренний номер,
пустые обязательные поля) при загрузке **пропускаются** — одна битая строка не
прерывает загрузку всего файла.

### Большой тестовый файл

`gradlew.bat sampleCsv` создаёт `data/contacts-large.csv` (около 1 МБ):

| Что внутри | Количество |
|---|---|
| корпоративные контакты (тот же генератор, что и кнопка «Сгенерировать») | 10 000 |
| аварийные контакты (read-only, их нельзя создать через GUI) | 10 |
| битые строки: неверное число полей, неизвестный тип, нечисловой номер, пустые обязательные поля, пустая строка | 8 |

При загрузке этого файла приложение сообщает: загружено 10 010 контактов,
пропущено 7 битых строк (пустая строка пропускается молча).
Файл удобен для проверки прогресс-бара, отмены загрузки и визуализации дерева.
Количество можно задать аргументом: `gradlew.bat sampleCsv 50000`.
Файл генерируется и в репозиторий не попадает (см. `.gitignore`).

## Модель

```text
Contact
├── EmergencyContact       // read-only, появляется только из CSV
└── CorporateContact       // implements Editable (должность, внутренний номер)
```

`Editable` — контракт «сущность можно изменять» с методом `validate()`.
Кнопка «Изменить» в GUI активна только для `CorporateContact`; через «Добавить»
создаётся только корпоративный контакт.

## Префиксное дерево (Trie)

Ключ индексации — имя контакта в нижнем регистре (`ru.litper.service.ContactService`),
поэтому поиск не зависит от регистра. Дерево реализовано на собственных узлах
и массивах: коллекции `java.util` как хранилище не используются.

```text
          (root)
          /    \
         м      н
        / \     / \
      а    р   а    а
      |    |   |    |
      р    к   т    т
      |    |   |    |
      и    (МАРК)  ш(наталья)
      / \
  н(марина) я(мария)
```

* `TrieNode` — символ, дети в **отсортированном массиве** (бинарный поиск),
  значения терминального узла (имена могут совпадать) и счётчик контактов
  в поддереве.
* `Trie<T>` — дженерики: в конструктор передаются класс элемента и `KeyExtractor`
  (как получить ключ из значения).
* Снаружи отдаются только геттеры: изменить узел из GUI нельзя.
* Каждая операция запоминает посещённые узлы (`lastTrace()`) и текст операции
  (`lastOperation()`) — по ним визуализация подсвечивает пройденный путь.

### Асимптотика

Обозначения: `L` — длина имени, `σ` — размер алфавита, `N` — число контактов,
`V` — число узлов, `K` — размер результата (поддерева/найденных контактов).

| Операция | O(...) | Обоснование |
|---|---|---|
| `insert` | O(L·log σ) | спуск по L символам, в узле бинарный поиск ребёнка; массив детей при вставке сдвигается |
| `findAll`, `findNode`, `contains` | O(L·log σ) | тот же спуск |
| `remove`, `removeKey` | O(L·log σ) | спуск + удаление из узла + подрезка пустых узлов (их ≤ L) |
| `removePrefix` | O(L·log σ + K) | спуск + отсоединение поддерева размера K |
| `autocomplete` | O(L·log σ + K) | спуск по префиксу + обход поддерева и сбор K контактов |
| `countByPrefix` | O(L·log σ) | спуск + чтение счётчика в узле (O(1)) |
| `toArray` | O(V + N) | обход всех узлов, дети уже отсортированы |

Сортировка детей даёт алфавитный порядок обхода «бесплатно» — поэтому
`toArray()` не требует сортировки.

### Сравнение с `java.util`

`gradlew.bat benchmark` (среднее из 5 прогонов, тот же набор ключей):

| Операция | N | своё Trie | `TreeMap` | отношение |
|---|---|---|---|---|
| вставка | 10⁴ | 17.10 мс | 5.52 мс | 3.10x |
| поиск по имени | 10⁴ | 0.11 мс | 0.04 мс | 2.75x |
| автодополнение (50) | 10⁴ | 0.19 мс | 0.35 мс | 0.55x |
| подсчёт по префиксу | 10⁴ | 0.08 мс | 0.63 мс | 0.12x |
| удаление | 10⁴ | 0.07 мс | 0.02 мс | 3.52x |
| вставка | 10⁵ | 37.46 мс | 16.83 мс | 2.23x |
| поиск по имени | 10⁵ | 0.06 мс | 0.03 мс | 1.80x |
| автодополнение (50) | 10⁵ | 0.20 мс | 0.11 мс | 1.80x |
| подсчёт по префиксу | 10⁵ | 0.03 мс | 0.10 мс | 0.31x |
| удаление | 10⁵ | 0.04 мс | 0.02 мс | 1.58x |

Выводы (цифры зависят от машины, сравнение — на одном наборе ключей):

* `TreeMap` быстрее на точных операциях: у него готовое красно-чёрное дерево,
  а у нас поиск ребёнка в массиве плюс поддержка счётчиков;
* своё дерево выигрывает на префиксных запросах, особенно на подсчёте:
  ответ берётся из счётчика за O(1), а `TreeMap` вынужден считать диапазон;
* `TreeMap` хранит один ключ — контакты с одинаковым именем схлопываются,
  Trie держит все значения в терминальном узле.

### Конкурентный доступ

`gradlew.bat raceDemo` — два потока по 10 000 увеличений:

```text
Без синхронизации: ожидалось 20000, получено 13989 — потеряно обновлений: 6011
Trie с synchronized: ожидалось 20000, получено 20000
Гонки нет: критическая секция защищена.
```

Защита в проекте:

* все публичные операции `Trie` объявлены `synchronized`;
* читающие методы возвращают **копии** (`toArray()`, `lastTrace()`), поэтому
  GUI-поток никогда не видит «наполовину перестроенную» структуру;
* тяжёлые операции (загрузка CSV, генерация) идут в фоновом потоке через
  `javafx.concurrent.Task`, интерфейс обновляется через `setOnSucceeded`.
